# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Unity project (Editor **6000.6.3f1**, see `ProjectSettings/ProjectVersion.txt`) demonstrating a reusable "life-cycle" pattern: a **SequenceManager** (game-state machine) and a **UIManager** (canvas registry) that run independently of each other, both accessed as singletons. The pattern is demonstrated on a minimal endless-runner in `Assets/_Game/Scenes/SampleScene.unity` (the only scene). `diagram.png` in the repo root illustrates the architecture.

Rendering uses **URP** (`com.unity.render-pipelines.universal`; pipeline asset in `Assets/_Game/Settings/`). The Built-In pipeline is deprecated in Unity 6.5+, so new materials must use URP shaders (e.g. `Universal Render Pipeline/Lit`, color in `_BaseColor`), not `Standard`.

Input uses the **Input System package** (`com.unity.inputsystem`); Active Input Handling is set to the new system only, so `UnityEngine.Input` (legacy `Input.GetAxis` etc.) will throw at runtime. The scene's EventSystem uses `InputSystemUIInputModule` with its default UI actions.

## Build / Run / Test

- There is no CLI build script; open the project in the Unity Editor and play `SampleScene`.
- No tests or assembly definitions exist — all scripts compile into `Assembly-CSharp`. `com.unity.test-framework` is installed if tests are added.
- `*.sln` / `*.csproj` are generated by Unity and gitignored (only `Life-Cycle-Asset.slnx` is tracked). `Assets/TextMesh Pro/` is also gitignored — on a fresh clone import TMP Essential Resources (Window > TextMeshPro) or the UI text won't render.
- Headless compile check (Windows, adjust Editor path): `"<Unity>/Editor/Unity.exe" -batchmode -quit -projectPath . -logFile -` — the Editor must not already have the project open.

## Architecture

All game code lives in `Assets/_Game/Scripts`, namespaced `_Game.Scripts.*` mirroring the folder path.

**Boot order** (`Sequence/Boot.cs`, on a scene object): `UIManager.InitializeUIManager()` (disables every canvas) → `SequenceManager.InitializeAllAppStates()` (calls `Initialize()` on every state) → `SequenceManager.ChangeState(startState)` (serialized in the scene; currently `Loading`). Wiring between states and canvases must happen in `Initialize()`, not `Awake`/`Start`, so it runs after UIManager is ready.

**App states** (`Base/AppState/AbstractAppState` : `MonoBehaviour, IState`):
- Each state is a MonoBehaviour on its own prefab in `Prefabs/AppStates/`, registered in `SequenceManager`'s serialized `AppStates` list and looked up by its `appStateType` field (`AppStateTypes` enum).
- `Base/StateMachine/StateMachine` is a plain C# class: `ChangeState` calls `Exit()` on the current state then `Enter()` on the new one. Only one state is active at a time.
- Base `Enter()`/`Exit()` throw `NotImplementedException` — every concrete state must override both.
- States own the flow: each state enables its canvas in `Enter`, disables it in `Exit`, and transitions by calling `SequenceManager.Instance.ChangeState(...)`. Current flow: `Loading → InGame ⇄ Pause`; `Pause → Counter (3-2-1) → InGame` on resume; `Pause → Reset → Loading → InGame` on reset.

**UI** (`Base/UserInterface/AbstractBaseCanvas`):
- Each canvas is a prefab in `Prefabs/Canvases/`, registered in `UIManager`'s serialized `canvases` list and looked up by `canvasType` (`CanvasTypes` enum). Multiple canvases may be enabled simultaneously.
- `Activate()`/`Deactivate()` toggle `Canvas.enabled` (not the GameObject) and call the `OnStart()`/`OnQuit()` hooks.
- Canvases don't reference states. They expose `OnUIButtonClickEvent` delegate fields (e.g. `PauseUI.Resume/Reset`, `InGameUI.Pause`) that the owning state assigns in `Initialize()`; Unity `Button.onClick` in the prefab calls the canvas method that invokes the delegate. States fetch typed canvases via `UIManager.Instance.GetCanvas(type) as XxxUI`.

**Gameplay** (`Gameplay/`): `PlayerController` moves only while `canControl` is true (toggled by `InGameState`) and publishes distance through `OnPositionChange`; `PlateSwapper` recycles `Plate` instances forward when the player triggers them. `GameResetState` resets both.

### Adding a state or canvas
1. Add a value to `AppStateTypes` (global namespace, `Enums/AppStateTypes.cs`) or `CanvasTypes` (`_Game.Scripts.Enums`). **Append only** — prefabs serialize these enums as integers, so reordering/inserting silently remaps every existing prefab.
2. Subclass `AbstractAppState` / `AbstractBaseCanvas`, create a prefab, set its type field in the Inspector.
3. Add it to the serialized list on `SequenceManager` / `UIManager` in `SampleScene` — lookup returns `null` (with only a `Debug.Log`) if it isn't registered.

## Conventions

- `AbstractSingleton<T>`: `Instance` lazily finds or creates the object; a duplicate destroys itself in `Awake`. Subclasses overriding `Awake` must call `base.Awake()`.
- Always commit `.meta` files alongside assets; Unity scene/prefab files are YAML and reference scripts by the GUID in those metas.
